## Section 8: Observations and Recommendations

### 8.1 What Worked Well

- **Fail-closed state checks:** Both stages repeatedly verified issue linkage, base branch, exact head SHA, nonempty diff, current-head CI, unresolved threads, and review identity before progressing.
- **Repository-owned validation:** Stage 30 ran the canonical Pester command in isolated worktrees. The suite grew from seven passing tests on [#8](https://github.com/edburns/dd-3068633-win32-x64-05/pull/8) to 16 on [#9](https://github.com/edburns/dd-3068633-win32-x64-05/pull/9).
- **Review effectiveness:** CCRA found a concrete contract-testing defect that CI did not catch. The local shepherd made a minimal one-file correction and obtained a clean exact-head re-review.
- **Serial dependency control:** The second task began only after the first task merged, allowing [#9](https://github.com/edburns/dd-3068633-win32-x64-05/pull/9) to build on the merged Fibonacci implementation without cross-branch coordination.
- **Control integrity:** `lessonPropagation` remained `off` in campaign metadata, run metadata, and every skill invocation. No campaign lessons were recorded or injected.
- **Cleanup:** Temporary review and validation worktrees were removed, and both task branches were deleted through the merge flow.

### 8.2 What Did Not Work Well

- PowerShell interpolation and nested quoting defects caused four avoidable command failures across stages 30 and 40.
- The expected-path comparison in the [#8](https://github.com/edburns/dd-3068633-win32-x64-05/pull/8) readiness gate rejected the correct two-file set because of expression-precedence behavior.
- One validation ran in the wrong current directory and received a success-shaped baseline result. The subsequent manual inspection caught it, but the runner's baseline behavior makes directory mistakes hazardous.
- The thread-resolution query returned a structured object that was not normalized before being passed back to GraphQL.
- OTEL redacted token-type labels, preventing an evidence-backed input/output split even though aggregate token counts were available.

### 8.3 Recommendations

1. **Move orchestration logic into tested helper scripts.** Replace long inline PowerShell commands with parameterized `.ps1` helpers covered by Pester tests for variable interpolation, regex quoting, array comparison, and GraphQL ID extraction.
2. **Use braced interpolation consistently before punctuation.** Generate messages with `${issue}` and `${task}` whenever a colon or another variable-name character can follow.
3. **Use set comparison for changed paths.** Standardize on `Compare-Object` plus explicit count checks rather than joined-string expressions whose precedence is easy to misread.
4. **Bind validation to an explicit working directory and SHA.** Invoke the canonical runner with a tool-level working-directory contract or begin each command by resolving and asserting `git rev-parse HEAD` and `Get-Location`. Treat the baseline "implementation absent" message as invalid when validating an implementation PR.
5. **Normalize API values at boundaries.** Convert GraphQL node IDs to strings immediately after parsing and validate they are nonempty before mutation calls.
6. **Create reusable review-request functions.** Centralize Copilot reviewer identity matching and avoid embedding escaped regular expressions inside nested `gh --jq` strings.
7. **Emit first-class run metrics.** Add per-phase start/end timestamps, issue/PR mapping, review IDs, comment counts, token input/output totals, premium requests, command retries, and merge commits to a machine-readable summary artifact. This would remove the need to reconstruct metrics from large Markdown transcripts.
8. **Preserve treatment comparability.** Keep lesson mode in every run summary and post-mortem. For this control run, explicitly record that task 2 inherited merged code but no propagated lesson text.

### 8.4 Overall Assessment

The campaign achieved full delivery with strong quality gates and rapid review convergence. The implementation pipeline behaved correctly, and the sole substantive review defect was fixed before merge. The main improvement opportunity is orchestration reliability: five recoverable shell failures and one success-shaped wrong-directory validation occurred in a 27-minute, two-task run. Converting repeated inline PowerShell into small tested helpers would reduce noise, shorten sessions, and make future treatment-versus-control comparisons more representative of agent performance rather than command-construction variance.
